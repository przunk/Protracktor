## R1 / C105 — overlapping playlist activation loses the latest selection

**Priority:** P2. **Evidence:** checked on the host with a controlled-store test; phone occurrence
and frequency are not checked. **Origin:** pre-existing, not introduced by C103 or B48.

**Locations:** [PlaylistSession.switchToPlaylist](../app/src/main/kotlin/com/przunk/protracktor/player/PlaylistSession.kt),
[writeSnapshot](../app/src/main/kotlin/com/przunk/protracktor/player/PlaylistSessionState.kt).

1. Restore playlist 1. Request playlist 2 and suspend its `tracksIn(2)` read.
2. Request playlist 3 and let its activation finish.
3. Release the earlier playlist-2 read.

Observed with unchanged production session/state code: persistence target `playlistId = 3`,
displayed `activePlaylistId = 2`, visible rows `[two]`. The correct-latest-selection assertion fails:
expected 3, actual 2. Each activation launches independently; there is no generation check or
serialization around its final publication. The switch method is byte-identical to baseline `79244e0`.

**Impact:** the older selection takes over the screen. C103 correctly rejects snapshots whose
displayed playlist differs from the persistence target, so it prevents writing these rows into
playlist 3. However, subsequent Save/automatic writes can be rejected until another activation
restores agreement. Ordinary Save returns silently when capture fails; notification Save reports
failure. These consequences follow from the production guards; they were not separate phone tests.
This is distinct from C103's fixed delayed-write and dirty-completion races.

**Recommendation:** separately approve a latest-request-wins activation fix. Guard all activation
publication/settings/resolution side effects, not just assigning one ID. Preserve C103's fail-closed
snapshot checks and add a permanent regression test for this exact suspended sequence.

## R2 — stale search completion can overwrite a newer query or another Browse domain

**Priority:** P2. **Evidence:** checked host characterization; phone timing not checked.
**Origin:** known retained Browse/navigation risk, not a new B46 regression or duplicate wishlist item.

**Locations:** [BrowseWorkflow.runSearch](../app/src/main/kotlin/com/przunk/protracktor/player/BrowseWorkflow.kt),
[existing characterization test](../app/src/test/kotlin/com/przunk/protracktor/player/BrowseWorkflowTest.kt).

Suspend search A, finish search B, enter History, then finish A. The existing test explicitly
asserts that History remains selected but A's rows replace the visible tracks. It passed again
in this review. `runSearch` captures the request correctly but publishes completion into whatever
Browse state now exists, without checking request ownership. The same ordering exists before B46.
Autocomplete's immediate submission does not create the defect, but makes consecutive searches easy.

**Recommendation:** extend the existing navigation-risk item with an explicit latest-request/domain
guard and cancellation/error handling. Protect live-result notices as well as rows/counts/loading.
Turn the adverse-behaviour characterization into a correctness regression when the fix is selected.
A green characterization suite is not evidence that stale results are safe.

## R3 — heart membership and display projection run on every progress tick

**Priority:** P2 measurement candidate. **Evidence:** code-inspected; slowdown/battery impact unmeasured.
**Origin:** new work from B48 and its presentation extraction, not a confirmed performance regression.

**Locations:** [PlaybackService subscriptions](../app/src/main/kotlin/com/przunk/protracktor/player/PlaybackService.kt),
[PlaybackPresentation](../app/src/main/kotlin/com/przunk/protracktor/player/PlaybackPresentation.kt),
[PlaylistHeart.of](../app/src/main/kotlin/com/przunk/protracktor/player/PlaylistHeart.kt).

The controller polls every 200 ms. On each emitted state, notification mapping derives the heart
before `distinctUntilChanged`; session metadata calls `contentOf` again; session playback state
derives the heart a third time. Each derivation scans the selected playlist until membership matches
(or to its end for a missing Browse/Random track). Metadata builds a `Content` including a heart it
does not use. Selected-language configuration contexts and display text are also reconstructed on
progress updates. Existing artwork caching limits bitmap creation; that does not eliminate these scans.

**Recommendation:** first measure a release build with a long selected playlist and an absent
Browse/Random track. If material, separate distinct metadata/heart inputs from position-only
PlaybackState updates. Do not introduce a second mutable membership cache without an invalidation
contract, and do not trade the stable saving-heart behaviour for fewer updates.

## R4 — MediaSession ARTIST now carries the full display summary

**Priority:** P2 compatibility question. **Evidence:** code/test-confirmed field mapping; external
controller behaviour not checked. **Origin:** intentional change in `6b4efca`, not an established bug.

**Location:** [PlaybackPresentation.metadata](../app/src/main/kotlin/com/przunk/protracktor/player/PlaybackPresentation.kt).

`DISPLAY_SUBTITLE` and `ARTIST` both contain author/platform/year, or loading/idle text. This
preserves the selected notification summary on clients using ARTIST as their second line, but
changes ARTIST's semantic value for Bluetooth receivers and other MediaSession consumers.
The application retains its original artist data; external consumers receive the composite value.
Existing presentation tests assert this mapping; they do not render a car/headset controller.

**Recommendation:** verify a real receiver's title/artist display before treating all external
metadata behaviour as unchanged. If the composite summary is undesirable outside SystemUI,
settle that trade-off explicitly; do not revert the owner-approved notification layout by assumption.

## R5 — audio-host tests cover ordering, not actual concurrent Oboe shutdown

**Priority:** P3 coverage gap. **Evidence:** host checks passed; concurrency/device stress not checked.
**Origin:** limitation of the new C102/B6 harness, not proof of a native memory bug.

**Locations:** [fake Oboe device](../scripts/audio-host-test/oboe/Oboe.h),
[native Player](../native/engine/player_oboe.cpp), [host checks](../scripts/audio-host-test/player_test.cpp).

Fake `render`, `fail`, `stop` and `close` execute synchronously. Tests exercise late-error ordering
and the real production Player/JNI paths, but fake stop does not wait for an in-flight audio
callback as the production code requires. They therefore do not prove lifetime safety while
recovery/close overlaps real audio/error threads. A previous ASan/UBSan pass is not a thread-race test.
The shared per-stream error object and control-thread ownership are sensible boundaries.

**Recommendation:** add a deliberately synchronized concurrent harness if this path is selected
for more work, then stress repeat connection/disconnection on a phone, including seeks and EOF.
Do not report a UAF or crash without a failing diagnostic. Mono's opposite-phase cancellation is
already documented and tested; it is not a newly discovered stereo bug.

## R6 — release APK signature verification fails open

**Priority:** P2 tooling risk. **Evidence:** control-flow inspection and shell syntax check only;
no invalid-APK run. **Origin:** inherited verifier behaviour in a script modified during this session.

**Location:** [build-release.sh](../scripts/build-release.sh).

The script suppresses `apksigner verify` failure via `|| true`, warns when the certificate cannot
be read or apksigner is absent, then prints final success. It also identifies a non-debug certificate
as a release key from its DN rather than an expected fingerprint. The new test-APK signing selector
keeps upload credentials out of this path, but the wrapper still does not enforce successful
signature verification. This is not evidence that the offered APK is invalid: its v2 signature
and expected test-certificate fingerprint were independently checked at handoff.

**Recommendation:** separately harden the wrapper to reject missing/failed verification and compare
the expected test certificate, using valid/unsigned/wrong-certificate disposable artifacts. Do not
inspect or use the owner's publishing key for this test.

## Positive observations and regression history

- C103 captures immutable identity plus contents, serializes writes and preserves newer dirty edits.
  R1 does not justify removing those guards.
- B48 binds both native action surfaces to track/playlist identity and keeps the action present
  during saves. Normal playlist editing does not acquire its deliberate full-save exception.
- The dock and notification share `NowPlayingText`; the P glyph is generated from existing geometry.
- B46 limits/filtering are pure, query history is separate from playback History, and the editable
  dropdown restores the explicitly selected input presentation without adding dependencies/schema.
- B6 processes PCM once in the common callback, with an Original bypass and bounded interpolation.
  Recovery retains decoder/position/mix rather than reopening the music file.
- Earlier missing-Previous placement, moving saving-heart and search-control style regressions
  remain recorded in the feature plans. They are corrected and owner-accepted, not reopened here.
